## Architecture
- `viewer/viewer.js` is the shared engine. It reads `window.DATA` (bones/<bone>/data/core.js) and `window.BONE` (bones/<bone>/content.js), and lazy-loads `data/layers.js`.
- A feature that applies to every bone goes in `viewer/`. Text and config for one bone go in that bone's `content.js` and `index.html`.
- `data/*.js` is generated by `pipeline/<bone>.py`. Never hand-edit it.
- Viewer coordinates are in mm, centred on the bone: X = patient's left, Y = up, Z = anterior. `common.Frame` converts from BodyParts3D coordinates (x = left, y = posterior, z = up).
- Bone mesh vertices carry region ids (`r`). These ids must match `REG` in content.js. Id 8 is reserved for the articular surface.
- Layers: rib, clav, muscle, artery, vein, nerve, lymph, organ, vert.

- Landmarks and attachments are measured from the meshes, not drawn by hand.
- A structure missing from BodyParts3D is built as a schematic fitted to measured landmarks, and the page must label it as schematic.
- Every bone needs review by an anatomy teacher before release.

## Engine features (viewer.js)
- Optional per-vertex part ids on a bone mesh (`p`), with `PARTS` keyed by id. Used by ribs for head, neck, tubercle, shaft and anterior end.
- Landmarks are drawn as typed markers with no visible name: elev, joint, groove, part, surf, num. `lmInfo` returns `type`. Tapping a marker shows its name and never moves the camera. Owner's rule: show only the markers on the side being viewed; markers on the far side (or hidden behind the bone) are hidden, not faded, and appear when the model is turned. Markers are THREE.Sprite objects inside the scene (sizeAttenuation off, depth-tested, lifted `mkLift` 3 mm toward the camera), so they move with the model every frame and the model itself hides far-side ones. Never go back to HTML overlay dots: the owner saw them lag while rotating. HTML is used only for the selected marker's name.
- Owner prefers dots over text labels: with `BONE.relAsMarkers`, `relLabels` ([key, name, mode, type]) become tap-to-name markers that follow the near-side rule (types art, ven, aus, open, node…). Vessel dots sit on the side the vessel is usually viewed from (`PREF` in heart.py).
- `BONE.startMode` sets the mode the page opens in (heart opens in `cor`).
- A landmark's `show` can be an array of modes, e.g. `['lm','joint']`.
- A REG entry with `lm:1` is tinted outside muscle mode, e.g. the vessel grooves on the 1st rib.
- Side trainer (mode `side`): needs `DATA.side = {R, L}`, plus `BONE.sideRules`, `sideView` and `sideDist`. Use it for every paired bone.
- Multi-specimen pages, e.g. ribs (first, second, typical, tenth, eleventh, twelfth): an inline loader picks `data/<spec>-core.js` from `#spec`. `content.js` picks `window.BONE` from `window.SPEC`. Elements carry `data-only="spec1 spec2"`; the ones not for the current spec are removed before the viewer runs.
- Which-number trainer (mode `which`): `BONE.whichSrc` (e.g. data/which.js, window.WHICH.items with `k`), plus whichNames, whichRules, whichQ, whichHint, whichView, whichDist. Built by `build_which()` in pipeline/vertebrae.py.
- `pipeline/vertebrae.py`: specs typical (T6), first, ninth, tenth, eleventh, twelfth. Parts 1–6 (body, pedicle, lamina, TP, spinous, articular). Facets come from rib contact.
- Organs (heart): the main mesh is still `group:'bone'` with `p` (chamber; +10 = inner wall), `r` (outer surface) and `t` (coronary territory). Mode options: `paint` ('parts'|'reg'|'terr'), `boneOp` (opacity), `cut`/`cuts` with `BONE.cuts[k] = {n, o, view}` (clipping plane, keep n·x >= o; slider in the legend), `clipLayers`, `legend` (STR list), `markers`. Landmarks may carry `cut` (shown only with that cut). `relLabels` entries can name a mode as 3rd item. `BONE.MK` overrides the marker legend; extra types `open`, `node`.
- `pipeline/heart.py`: voxelises the wall (FMA7274) plus great vessels; the two closed cavities are split at the AV annulus plane into RA/RV/LA/LV; auricles by morphological opening. Epicardium = surface facing the outside space. Surfaces by visibility (front/below/behind/left). Exports cuts, measurements (`meas`) and Datta's surface marking fitted to this subject's cartilages. Cache in `.cache/`.
- `pipeline/limb.py [bone...]`: clavicle, scapula, humerus, radius, ulna, hand (right side; left only for the side trainer). Muscle attachments = scan contact (2.5 mm) restricted to the zone Datta describes (`Z` per bone: t-range along the long axis + facing direction, or a vertex mask), because MRI muscles touch bone in many places. Joint surfaces: within `jt` mm of the nearest distance to the neighbour bone (MRI joints have gaps). Scapula processes are split by mesh connectivity. Hand = all 27 right-hand bones in one mesh, part id per bone; `which` trainer for the 8 carpals; side trainer uses the scaphoid.
- `tools/limbpage.py` + `tools/pages_upper.py [bone...]` write the limb pages' index.html; `#tbl-att` is filled from REG by viewer.js.
- `pipeline/ribs.py`: `python pipeline/ribs.py [spec ...]`. Each spec has `kind` and `tub` (False for 11th and 12th, which have no neck or tubercle). `cart` may be None, in which case the pointed tip is used as the anterior end.
